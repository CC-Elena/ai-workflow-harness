# 步骤二：任务拆分

将 `prd.yaml` 拆分为可执行的开发任务。

## 前置条件

- 已完成 `skills/feature-dev/action-extract.md`，存在 `prd.yaml`

## 拆分前检查

**必须完成以下检查**：
- [ ] 已搜索 `components-catalog.json` 确认可复用组件
- [ ] 已搜索 `src/utils/` 确认现有工具函数
- [ ] 已搜索 `src/service/` 确认现有 API 服务
- [ ] 已了解相关模块现有代码结构

## 拆分原则

**粒度判断**
- **太大**：超过 2 天、涉及 3+ 模块
- **太小**：少于 2 小时、单函数修改
- **刚好**：0.5-2 天，独立可测试

**避免重复**
- 功能已在另一任务中实现 → 合并或标注"已包含"
- 工具函数和持久化可合并同一任务

## 产出

创建 `docs/prd-tasks/{功能名}/tasks.md`

## 任务格式

```markdown
# [功能名称] 开发任务

## 概览

- **PRD 来源**：[链接]
- **任务数量**：N 个
- **预估工时**：X 人天

## 依赖关系

T1 ──→ T3
T2 ──→ T3

## 任务列表

### T1：[任务名称]

**基本信息**
- 类型：API对接 | 组件开发 | 页面开发 | 状态管理
- 复杂度：L(<0.5天) | M(0.5-1天) | H(1-2天)
- 复用：新建 | 复用 ComponentName

**描述**
一句话说明

**涉及文件**
- `src/xxx` - 新增/修改

**验收条款**
- [ ] 验收条件 1
- [ ] 验收条件 2

**依赖**：无 | T1
```

## 完成标志

- [ ] 已创建 `tasks.md`
- [ ] 每个任务有明确验收条款
- [ ] 人工确认任务粒度合理
