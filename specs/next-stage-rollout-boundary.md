# 下一阶段推广范围和风险边界

本文档承接 `开发计划.md` 阶段 8 的验收项：明确下一阶段推广范围和风险边界。

## 1. 推广范围

下一阶段只推广已经在本仓库中跑通的仓库资产型工作流：

1. PRD 或用户需求转换为结构化 Spec。
2. 基于 Spec 拆解 Tasks。
3. 使用上下文索引和 Skill 路由执行低风险代码修改。
4. 运行 `npm run lint`、`npm run typecheck`、`npm run build`。
5. 对 UI 改动执行桌面和移动端截图检查。
6. 沉淀 Run Record、Verification Record 和必要时的 RCA。

## 2. 推荐试点类型

优先选择以下低风险需求：

1. 文档资产维护。
2. 首页或工具页的静态信息展示。
3. 表单字段扩展和 localStorage 草稿能力。
4. 静态资产索引或分类调整。
5. 不涉及权限、支付、生产数据、核心业务接口的 UI 小改动。

## 3. 暂不推广范围

以下能力不进入下一阶段推广：

1. MCP 企业知识库接入。
2. 自研 Agent Runtime。
3. 独立 SaaS 平台。
4. 数据库、后端接口或自动发布流程。
5. 完全无人值守修改和合并。
6. 高风险核心链路修改。
7. 自动统计 MVP 概览或自动扫描 Markdown 文件。

## 4. 风险边界

| 风险 | 边界 | 处理方式 |
|------|------|----------|
| Spec 不清晰 | 不进入 Executor | 先补充待确认问题 |
| 涉及核心模块 | 不自动修改 | 明确人工授权后再执行 |
| 验证失败 | 不扩大修改范围 | 先判断是否由本次变更引入 |
| UI 变更 | 必须截图检查 | 至少覆盖桌面和移动端 |
| 文档状态与页面状态不一致 | 视为资产维护问题 | 同步更新首页资产列表和任务概览 |
| 人工大幅修改 AI 产物 | 必须生成 RCA | 反哺 Prompt、Skill 或上下文索引 |

## 5. 推广准入标准

一个新需求进入该工作流前必须满足：

1. 有明确 PRD、用户需求或待办说明。
2. 可生成结构化 Spec。
3. 能拆成可独立验证的任务。
4. 影响范围可被上下文索引定位。
5. 有可运行的验证命令或明确跳过理由。
6. 不属于暂不推广范围。

## 6. 推广成功标准

下一阶段成功的最低标准：

1. 至少 3 个新增低风险需求完整跑通闭环。
2. 每个需求都有 Spec、Tasks、Run Record。
3. UI 需求都有截图验证记录。
4. 至少一次失败或人工修改能生成 RCA。
5. 所有新增规则都能沉淀到 `.ai/`、`skills/` 或 `docs/` 中。
