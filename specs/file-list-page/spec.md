# Feature Spec: file-list-page

## 1. 基本信息

- 需求名称：文件列表页
- 需求来源：产品需求（用户截图参考 Google Drive 文件管理界面）
- 负责人：AI Agent
- 创建日期：2026-05-09
- 状态：Implemented

## 2. 背景与目标

当前首页将仓库资产检索嵌入在工作流主页中，缺乏独立的文件管理视角。随着资产数量增多，用户需要一个专属页面来纵览和管理所有文件，并能将高频使用的文件「置顶」以快速定位。

目标：新增独立的 `/files` 页面，复用现有 harness 方案，提供文件列表展示和置顶功能。

## 3. 范围

### 3.1 本次包含

1. 新增 `/files` 路由页面。
2. 以列表/表格形式展示所有仓库资产文件。
3. 支持置顶操作，置顶文件以卡片网格展示在页面上半部分。
4. 支持搜索过滤和分类筛选。
5. 置顶状态持久化到 `localStorage`。
6. 添加全局导航栏，支持首页/文件列表页切换。

### 3.2 本次不包含

1. 不开发文件系统扫描（不使用 `fs` 模块）。
2. 不读取真实文件内容。
3. 不开发后端接口。
4. 不修改首页现有功能。
5. 不实现文件排序功能（后续迭代）。

## 4. 用户场景

| 场景 | 用户行为 | 期望结果 |
|------|----------|----------|
| 查看所有文件 | 导航到 `/files` 页面 | 看到所有仓库资产文件列表 |
| 置顶高频文件 | 点击文件行的「置顶」按钮 | 文件出现在顶部卡片区 |
| 取消置顶 | 点击卡片或列表中的「取消置顶」按钮 | 文件从卡片区移除 |
| 搜索文件 | 在搜索框输入关键词 | 列表按标题/路径/描述过滤 |
| 按分类筛选 | 点击分类标签按钮 | 列表仅显示该分类文件 |
| 导航切换 | 点击导航栏「首页」 | 跳转到工作流首页 |
| 刷新保持 | 刷新页面 | 置顶状态不丢失 |

## 5. 功能要求

| 编号 | 功能点 | 说明 | 优先级 |
|------|--------|------|--------|
| F1 | 文件列表展示 | 复用 `workflow-data.ts` 的 `assets` 数据，以表格行形式展示 | P0 |
| F2 | 置顶操作 | 每行文件提供置顶/取消置顶按钮 | P0 |
| F3 | 置顶卡片区 | 页面上半部分以 4 列 grid 展示已置顶文件卡片 | P0 |
| F4 | 搜索过滤 | 按标题/路径/描述模糊搜索 | P0 |
| F5 | 分类筛选 | 复用现有分类标签 | P0 |
| F6 | 导航栏 | 全局导航支持页面切换 | P1 |
| F7 | 置顶持久化 | `localStorage` 存储置顶状态 | P1 |
| F8 | 空态处理 | 无置顶文件时不显示卡片区 | P1 |

| 数据 | `src/lib/data/file-data.ts` [NEW] | 文件列表扩展数据 |
| 布局 | `src/app/layout.tsx` | 添加全局导航栏 |

## 7. 数据与接口

| 接口或数据源 | 请求/输入 | 响应/输出 | 约束 |
|--------------|-----------|-----------|------|
| `workflow-data.ts` 中的 `assets` 数组 | 页面内静态导入 | 资产文件列表 | 不新增接口 |
| `localStorage` | `ai-workflow-pinned-files` key | 置顶文件路径数组 | JSON 序列化 |

## 8. 权限与异常场景

| 场景 | 处理方式 |
|------|----------|
| 无置顶文件 | 隐藏置顶卡片区，仅显示文件列表 |
| 搜索无结果 | 显示空列表，文件计数为 0 |
| 分类无匹配 | 显示空列表 |
| `localStorage` 损坏 | 清空并重置置顶状态 |

## 9. 设计与交互约束

1. 设计稿：已生成 AI 设计稿，参考 Google Drive 风格。
2. 复用现有 `.page-shell`、`.section-block` 布局类名。
3. 复用现有 CSS 变量（`--accent`、`--surface`、`--line` 等）。
4. 置顶卡片区使用 4 列网格，响应式降级为 2 列 / 1 列。
5. 文件列表使用表格样式行，含表头。

## 10. 工程约束

1. 不新增依赖。
2. 复用 Next.js App Router 路由。
3. 复用 `workflow-data.ts` 中的类型和数据。
4. 文件命名使用英文短横线。
