# PRD：文件列表页

## 1. 背景

AI Workflow Harness 首页已有「仓库资产检索」模块，但资产条目以行列表嵌入在工作流主页中，缺乏独立的文件管理视角。当资产数量增多后，用户希望：

1. 在一个独立页面中纵览所有仓库文件。
2. 将高频使用的文件「置顶」，以卡片形式常驻页面顶部，实现快速定位。
3. 类似 Google Drive 的文件管理体验：上半部分为置顶/收藏区（卡片），下半部分为完整文件列表（表格）。

## 2. 目标

1. 新增独立的「文件列表页」，以列表形式展示当前代码库中的所有资产文件。
2. 支持文件「置顶」操作，置顶后的文件以卡片形式展示在页面上半部分。
3. 保持搜索和分类筛选能力。
4. 复用现有 harness 方案（Next.js App Router + TS 数据 + 全局 CSS 变量）。

## 3. 功能需求

1. **文件列表展示**：复用现有 `workflow-data.ts` 中的 `assets` 数据，以表格行形式展示文件名称、路径、分类、修改时间。
2. **置顶功能**：每行文件提供「置顶/取消置顶」按钮，点击后文件出现在顶部卡片区。
3. **置顶卡片区**：页面上半部分以 4 列 grid 卡片形式展示已置顶文件，包含文件图标、名称、分类和取消置顶按钮。
4. **搜索过滤**：支持按文件名/路径/描述搜索。
5. **分类筛选**：复用现有分类标签（All / Workflow / Template / Context / Spec / Evaluation / Skill）。
6. **导航切换**：页面间可通过顶部导航在「首页」和「文件列表」间切换。
7. **持久化**：置顶状态保存在 `localStorage`，刷新页面后保持。

## 4. 非目标

1. 不开发文件系统扫描能力（不使用 `fs` 模块动态读取目录）。
2. 不读取真实文件内容。
3. 不开发后端接口。
4. 不修改首页现有功能逻辑。

## 5. 设计参考

参考 Google Drive 的文件管理界面：
- 上半部分：置顶/收藏的文件以卡片网格展示。
- 下半部分：所有文件以列表/表格形式展示，含排序和操作按钮。

## 6. 验收标准

1. 访问 `/files` 可看到文件列表页。
2. 页面上半部分以卡片展示已置顶的文件。
3. 页面下半部分以列表展示所有文件，支持搜索和分类筛选。
4. 点击置顶按钮后文件出现在卡片区，刷新页面后状态保持。
5. 顶部导航可在首页和文件列表页之间切换。
6. `npm run build` 通过。
