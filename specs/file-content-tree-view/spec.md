# Feature Spec: file-content-tree-view

## 1. 基本信息

- 需求名称：文件内容预览与目录树组织
- 需求来源：用户需求
- 负责人：AI Agent
- 创建日期：2026-05-09
- 状态：Implemented

## 2. 背景与目标

当前文件列表页只能展示资产文件元信息，缺少文件夹组织和内容查看能力。目标是在 `/files` 页面提供一个资产文件浏览器：左侧按仓库路径展示目录树，右侧展示选中文件内容。

## 3. 范围

### 3.1 本次包含

1. 新增只读文件内容 API。
2. 基于现有 `assets` 数据构建目录树。
3. 重构 `/files` 页面为目录树 + 内容预览布局。
4. 保留搜索、分类筛选和置顶功能。
5. 增加加载、错误和空态。
6. 补齐本次需求的 harness 记录和验证证据。

### 3.2 本次不包含

1. 不扫描全仓库文件。
2. 不允许读取资产清单外路径。
3. 不支持编辑、删除、重命名、下载、复制。
4. 不做 Markdown 渲染或语法高亮。

## 4. 功能要求

| 编号 | 功能点 | 说明 | 优先级 |
|------|--------|------|--------|
| F1 | 目录树 | 按 `assets[].path` 构建 folder/file 节点 | P0 |
| F2 | 内容读取 API | `GET /api/files/content?path={assetPath}` | P0 |
| F3 | 内容预览 | 右侧展示选中文件内容和元信息 | P0 |
| F4 | 范围限制 | API 只允许读取 `assets` 清单路径 | P0 |
| F5 | 筛选联动 | 搜索和分类筛选更新目录树 | P1 |
| F6 | 置顶兼容 | 保留现有 localStorage 置顶能力 | P1 |
| F7 | 响应式布局 | 桌面左右分栏，移动端上下布局 | P1 |

## 5. 页面与组件影响

| 类型 | 名称或路径 | 变更说明 |
|------|------------|----------|
| API | `src/app/api/files/content/route.ts` [NEW] | 受限读取资产文件内容 |
| 数据 | `src/lib/data/file-data.ts` | 增加目录树类型和构建函数 |
| 页面组件 | `src/components/views/file-workspace.tsx` | 改为目录树和内容预览 |
| 样式 | `src/app/globals.css` | 增加文件浏览器布局和预览样式 |

## 6. 数据与接口

| 接口或数据源 | 请求/输入 | 响应/输出 | 约束 |
|--------------|-----------|-----------|------|
| `assets` | 静态导入 | 资产文件列表 | 作为唯一可读路径白名单 |
| `/api/files/content` | `path` query | `{ path, content, size }` | 只读、白名单、文本读取 |
| `localStorage` | `ai-workflow-pinned-files` | 置顶路径数组 | 沿用现有 key |

## 7. 异常场景

| 场景 | 处理方式 |
|------|----------|
| 请求未登记路径 | 返回 404 和 `{ error }` |
| 文件读取失败 | 返回 404 和 `{ error }` |
| 筛选无结果 | 左侧显示空态，右侧显示无匹配文件 |
| 内容加载中 | 右侧显示加载态 |
| localStorage 损坏 | 清空并重置置顶状态 |

## 8. 设计与交互约束

1. 使用左侧目录树、右侧预览布局。
2. 文件内容使用等宽字体，保留换行。
3. 内容区域内部滚动，不撑破页面。
4. 移动端上下布局，无横向溢出。
5. 不使用额外依赖。

## 9. 工程约束

1. 使用 Next.js App Router route handler 实现 API。
2. API 不允许任意路径读取。
3. 复用现有 `Asset`、`AssetCategory` 和 `assets` 数据。
4. 不新增数据库、后端服务或 MCP 能力。

| A6 | 置顶刷新后保持 | 浏览器验证 |
| A7 | 移动端无横向溢出 | 浏览器验证 |
| A8 | 静态检查、构建、harness 门禁通过 | 命令验证 |
