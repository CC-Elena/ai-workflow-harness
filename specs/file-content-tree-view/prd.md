# PRD：文件内容预览与目录树组织

## 1. 背景

现有 `/files` 页面已经能展示资产文件列表，并支持搜索、分类筛选和置顶。但用户只能看到文件名称、路径和描述，无法直接在网页上查看文件内容，也无法按当前仓库目录结构理解文件之间的组织关系。

## 2. 目标

1. 在网页上查看每个资产文件的真实文本内容。
2. 按文件当前路径组织目录树，引入文件夹概念。
3. 保留现有搜索、分类筛选和置顶能力。
4. 限定读取范围为现有资产清单，避免任意文件读取。

## 3. 功能需求

1. **目录树展示**：按 `assets[].path` 构建文件夹/文件树，例如 `.ai/workflows/*`、`.ai/templates/*`、`specs/*`。
2. **内容预览**：点击目录树中的文件后，右侧展示文件标题、路径、分类、描述和文本内容。
3. **受限读取 API**：通过服务端接口读取文件内容，只允许读取 `workflow-data.ts` 中登记的资产路径。
4. **筛选联动**：搜索和分类筛选后，目录树只展示匹配文件及其父级目录。
5. **置顶保留**：置顶/取消置顶能力继续可用，刷新后仍保留。
6. **响应式布局**：桌面为左侧目录树、右侧预览；移动端降级为上下布局。

## 4. 非目标

1. 不做全仓库扫描。
2. 不读取未登记在 `assets` 清单中的文件。
3. 不开发编辑、删除、重命名、下载或复制能力。
4. 不做 Markdown 渲染、语法高亮或二进制文件预览。

## 5. 验收标准

1. 访问 `/files` 可看到目录树和右侧内容预览。
2. 点击任意资产文件后，右侧显示该文件真实内容。
3. 请求 `/api/files/content?path=.ai/workflows/README.md` 返回文件内容。
4. 请求 `/api/files/content?path=package.json` 返回失败。
5. 搜索和分类筛选会更新目录树。
6. 置顶/取消置顶仍可用并持久化。
7. 移动端无横向溢出。
8. `npm run lint`、`npm run typecheck`、`npm run build`、`npm run harness:check -- specs/file-content-tree-view` 通过。
