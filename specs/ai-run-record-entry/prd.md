# 模拟 PRD：AI 工作流执行记录入口

## 1. 背景

AI Workflow Harness 已经沉淀了 Spec、Task、Run Record、RCA 等工作流资产，但当前使用者进入仓库后，需要自己在 `.ai/`、`specs/`、`skills/` 多个目录之间查找入口。

为了降低首次使用成本，希望在仓库内新增一个清晰的“执行记录入口说明”，帮助研发同学快速完成一次 AI 辅助需求的记录。

## 2. 目标

让研发同学在完成一次 AI 辅助需求后，可以快速知道：

1. Run Record 应该记录什么。
2. RCA 什么时候需要生成。
3. 执行记录应该放在哪里。
4. 如何从一次执行记录反哺 Prompt、Skill 或上下文索引。

## 3. 用户角色

1. 研发工程师：完成 AI 辅助需求后填写执行记录。
2. 技术负责人：通过执行记录评估 AI 工作流效果。
3. 后续接入者：通过历史记录学习标准流程。

## 4. 功能需求

### 4.1 新增执行记录入口说明

在 `.ai/evals/` 下提供更明确的入口说明，包含：

1. Run Record 的使用时机。
2. RCA 的使用时机。
3. 推荐文件路径。
4. 最小填写示例。
5. 常见错误。

### 4.2 新增一次模拟执行记录

在 `specs/ai-run-record-entry/` 下生成一次完整模拟执行记录，用于验证工作流。

需要包含：

1. `prd.md`
2. `spec.md`
3. `tasks.md`
4. `run-record.md`

### 4.3 不进入真实业务代码修改

由于当前试点目标是验证工作流文档链路，不修改业务代码。

## 5. 非目标

1. 不开发 UI 页面。
2. 不接入数据库。
3. 不开发独立执行记录平台。
4. 不自动统计指标看板。

## 6. 验收标准

1. `specs/ai-run-record-entry/run-record.md` 能说明本次模拟链路。
2. `specs/ai-run-record-entry/tasks.md` 至少拆解 3 个可执行任务。
3. `specs/ai-run-record-entry/run-record.md` 记录本次模拟执行结果。
4. `.ai/evals/README.md` 能作为执行记录入口说明使用。
5. 本次试点不修改真实业务代码。
