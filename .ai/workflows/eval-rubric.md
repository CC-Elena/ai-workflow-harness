# AI 工作流评分 Rubric

本文档提供可复制的 1-5 分 Rubric，用于人工评审或 LLM-based grader。

## 1. 评分原则

1. 先检查阻断项，再评分。
2. 能用确定性检查的指标不使用主观评分。
3. 主观评分必须使用清晰等级描述。
4. 评分必须给出证据文件或证据段落。
5. 分数低于 4 的维度必须给出改进建议。

## 2. 通用等级

| 分数 | 含义 |
|------|------|
| 5 | 完整、清晰、可直接复用，无明显缺口 |
| 4 | 基本完整，仅有轻微可改进点 |
| 3 | 可用但存在明显缺口，需要补充 |
| 2 | 部分可用，缺口会影响执行质量 |
| 1 | 不可用或严重不符合要求 |
| 0 | 缺失或出现阻断项 |

## 3. Spec 质量 Rubric

| 分数 | 标准 |
|------|------|
| 5 | 背景、目标、范围、非目标、场景、功能、影响、验收、风险全部清楚 |
| 4 | 主要内容完整，少量边界或风险可补充 |
| 3 | 有核心需求，但验收、风险或影响范围不够明确 |
| 2 | 需求描述散乱，Planner 需要大量猜测 |
| 1 | 无法指导任务拆解 |
| 0 | 缺失 Spec |

## 4. 任务拆解 Rubric

| 分数 | 标准 |
|------|------|
| 5 | 每个任务原子化、依赖清楚、影响范围明确、可独立验证 |
| 4 | 任务基本可执行，少量验证或风险描述可增强 |
| 3 | 任务可执行但粒度偏大或依赖不清 |
| 2 | 多个无关目标混在一起，失败后难定位 |
| 1 | 任务无法直接执行 |
| 0 | 缺失 Tasks |

## 5. 上下文与 Skill 使用 Rubric

| 分数 | 标准 |
|------|------|
| 5 | 正确读取项目上下文、相关索引和匹配 Skill，无遗漏关键约束 |
| 4 | 读取了主要上下文，少量非关键上下文缺失 |
| 3 | 基本能执行，但上下文召回不足或 Skill 使用不完整 |
| 2 | 明显漏读关键上下文，导致实现风险 |
| 1 | 未使用已有上下文或 Skill |
| 0 | 因上下文错误导致任务失败 |

## 6. 执行质量 Rubric

| 分数 | 标准 |
|------|------|
| 5 | 修改最小、符合架构、无越界、无无关重构 |
| 4 | 修改合理，存在轻微可清理点 |
| 3 | 功能完成但有范围膨胀或局部风格偏差 |
| 2 | 实现可运行但明显不符合工程约束 |
| 1 | 实现大部分不可采纳 |
| 0 | 修改破坏核心能力或越权 |

## 7. 验证质量 Rubric

| 分数 | 标准 |
|------|------|
| 5 | 应运行的验证均运行并记录，UI 任务有截图验证 |
| 4 | 主要验证完整，少量低风险项跳过且解释充分 |
| 3 | 有基本验证，但缺少重要验证项 |
| 2 | 验证不足，无法支撑交付判断 |
| 1 | 验证记录与事实不一致 |
| 0 | 未验证却记录 Pass |

## 8. 记录与 RCA Rubric

| 分数 | 标准 |
|------|------|
| 5 | Run Record 完整，必要时 RCA 有根因、修复、反哺项 |
| 4 | 记录完整，复盘建议略粗 |
| 3 | 有记录但缺少指标或风险说明 |
| 2 | 记录无法支撑复盘 |
| 1 | 记录与实际执行明显不一致 |
| 0 | 应记录但缺失 |

## 9. LLM Grader 输出格式

```json
{
  "dimension": "Spec quality",
  "score": 4,
  "evidence": ["specs/example/spec.md#验收标准"],
  "rationale": "Spec 覆盖主要范围，但风险边界可更具体。",
  "improvements": ["补充权限和异常场景"]
}
```
