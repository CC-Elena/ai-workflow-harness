# AI 工作流能力边界

本文定义本仓库 AI 研发工作流与 Codex 等 Coding IDE 的职责边界。

## 1. 本项目不建设的能力

以下能力由 Codex、Cursor、Claude Code 等 Coding IDE 提供，本仓库不重复开发：

1. 代码读取、搜索、理解。
2. 多文件编辑和 Patch 应用。
3. 终端命令执行。
4. Lint、Typecheck、Test、Build 调用。
5. Git diff、变更摘要和代码 Review。
6. 基于上下文的代码生成。
7. 浏览器访问、截图和页面验证。
8. 长任务执行中的人工协作。
9. 工具调用编排。
10. 模型选择和模型运行。

## 2. 本项目建设的能力

本仓库只沉淀 AI 执行所需的工程资产：

1. Spec 模板和示例。
2. Planner-Executor 工作流协议。
3. Prompt 模板。
4. 项目上下文索引。
5. Skills 路由规则。
6. 校验协议。
7. Run Record 模板。
8. RCA 模板。
9. 工程规范入口。

## 3. 协作方式

```text
仓库资产提供规则、上下文和验收标准
        ↓
Codex 读取资产并执行规划、编辑、验证
        ↓
执行结果回写到 Run Record 和 RCA
        ↓
RCA 反哺 Spec、Prompt、Skill 和上下文索引
```

## 4. 判断标准

如果某项能力属于“执行代码修改或运行工具”，优先交给 Codex。

如果某项能力属于“告诉 Codex 应该如何理解项目、如何拆解任务、如何验证结果”，沉淀到仓库。

## 5. 当前 MVP 边界

MVP 包含：

1. `.ai/` 工作流目录。
2. Spec 模板和示例。
3. Planner-Executor 协议文档。
4. 上下文索引文档。
5. Skills 路由说明。
6. 校验协议。
7. 执行记录模板。
8. RCA 模板。
9. 一个真实需求试点。

MVP 不包含：

1. 独立平台。
2. 自研 Agent Runtime。
3. 自研代码编辑器。
4. 模型调度系统。
5. 复杂可视化看板。
6. 自动发布系统。
